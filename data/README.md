# Data directory

| Directory | Contents | Git |
| --- | --- | --- |
| `raw/` | Source data exactly as obtained, unmodified | ignored |
| `processed/` | Derived datasets the pipeline reads | ignored, `README.md` tracked |
| `external/` | Cached third-party responses | ignored |

## Provenance

`processed/observations.csv` and `processed/districts.csv` are generated by
`scripts/generate_demo_dataset.py` with a fixed seed. They are **synthetic**.

The generator models monsoon seasonality with a latitude-dependent peak, an AR(1)
regional weather state for spatial coherence, gamma-distributed daily totals and
per-gauge multiplicative error. It is a development convenience, not a data
source. No number derived from it is a claim about real rainfall.

## Schema

`observations.csv` — one row per district per day:

```csv
district_id,observed_at,rainfall_mm,lat,lon
MH-MUM,2026-09-28 00:00:00+00:00,12.4,19.2183,72.9781
```

`district_id` may be the numeric id from `districts.csv` or its `code`; the
loader normalises to the numeric id.

`districts.csv`:

```csv
id,code,name,region,centroid_lat,centroid_lon,population
1,MH-MUM,Mumbai Suburban,Maharashtra,19.2183,72.9781,2335000
```

## Regenerating

```bash
ml/.venv/bin/python scripts/generate_demo_dataset.py --years 3 --seed 42
```

Overwrites both files. The same seed produces the same data.

## Using real data

1. Obtain district-level daily rainfall from an open source (for example the
   India Meteorological Department, or ERA5 via the Copernicus Climate Data
   Store).
2. Write `observations.csv` with exactly the schema above. One row per district
   per calendar day; gaps are acceptable, they are imputed as 0 mm during
   cleaning.
3. Write `districts.csv` with the district dimension.
4. Set `ML_TRAINING_DATA_PATH` to the directory and re-run
   `scripts/run_training.py`.
5. Ingest into the API with `POST /api/v1/observations/ingest`, then run
   verification.

No code changes are needed. The loaders, the feature pipeline and the training
configuration all read this schema.

## Retention

Raw downloads are kept as-is so a re-run is reproducible. Processed files are
regenerable and are not committed. Model artifacts are rebuilt with
`scripts/run_training.py`; they are ignored for the same reason.
