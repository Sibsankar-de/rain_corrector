# Training dataset

Files written by `scripts/generate_demo_dataset.py`:

| File | Contents |
| --- | --- |
| `observations.csv` | Long format: `district_id, observed_at, rainfall_mm, lat, lon` |
| `districts.csv` | District dimension: `id, code, name, region, centroid_lat, centroid_lon, population` |

## Provenance

> **This dataset is synthetic.** It is generated by
> `scripts/generate_demo_dataset.py` with a fixed seed and models monsoon
> seasonality, spatial coherence and intermittent events. It is **not** IMD,
> ERA5 or gauge data and must not be cited as a real rainfall record.

The generator is a development convenience. Its only purpose is to make the
training, verification and API paths runnable end to end on a clean checkout.

## Replacing with real data

1. Obtain a district-level daily rainfall series from an open source
   (for example the India Meteorological Department, or ERA5 via the Copernicus
   Climate Data Store).
2. Write a CSV with exactly the `observations.csv` schema above, keyed by
   `district_id` matching your `districts.csv` codes.
3. Update `ML_TRAINING_DATA_PATH` and re-run `scripts/run_training.py`.
4. Ingest into the API with `POST /api/v1/observations/ingest` and re-run
   verification.

No code changes are required: the loaders, feature pipeline and training
configuration all read the same schema.
